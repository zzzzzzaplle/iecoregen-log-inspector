# 分析日志

## 阶段

分析日志格式，确定核心功能边界。

## 样例

- 样例日志：`logs/AI-Games-Hex/deepseek-v4-flash/hexgame2/log.txt`
- 样例单位：`AI-Games-Hex/deepseek-v4-flash/hexgame2#sample2.mwe2`

## sample开始/结束

- sample 开始：`[deepseek-v4-flash] 正在启动 sample2.mwe2...`
- sample 结束：`sample2.mwe2 启动完成`
- 样例中从 <sample 开始> 到 `reactor.util.Loggers -- Using Slf4j logging framework` 之前视为无效前缀，主要是启动、依赖扫描、项目注册等噪声。

## 日志异常/错误模式
分析每个 sample 前，先扫描异常/错误模式,如果有错误模式需要额外标注这些信息的行号
目前已整理的错误模式有
举例
- Caused by: java.io.EOFException: EOF reached while reading 
报错pattern (只要日志里有报错就肯定会有这句话,但有这句话不一定说明该日志出错)
- Cannot invoke "java.lang.Iterable.iterator()" because "iterable" is null
- Caused by: xxxx

如果在同一个 sample 内出现 `Cannot invoke "java.lang.Iterable.iterator()" because "iterable" is null`,
说明此前的 EOperation 标注/校验尝试失败。解析时需要找到该 sample 内最后一次此报错的位置,
并以后续第一次出现的 `Annotating EOperations` 作为该 sample 的有效流程发起起点。

## 其他分析
### 你看到有些request 发起”两次“的原因

同一个 prompt 内容可能会在日志里出现两次，但不一定代表发了两次请求。一次是 iecoregen 自己的 LOG.info("Prompt")，另一次是 Spring AI DEBUG 把 HTTP 请求体里的 rawContent 又完整打印了一遍。
你比如一次的开头是
842715 [main] INFO  du.ustb.sei.mde.mwe2.EcoreGenerator  - Prompt:
# Task
You will be given a **Requirement**, a **Class Diagram** in PlantUML, and a list of operation specifications. Your task is to correct the specifications that are inconsistent with the requirement.
   这是Iecoregen自己打印的,这是因为源代码中是这么写的: 
   while(count < maxRepeat) {
    val prompt = getVerificationPrompt(req, cd, operations)
    LOG.info('Prompt:\n'+prompt)

    val result = port.queryString(prompt, languageID)
    ...
    count += 1
   }
   而queryString里面打印一次 因为 queryString(prompt, languageID) 会把这个 prompt 包装进 ChatCompletion 的 messages[0].rawContent，所以你会在 DEBUG 日志里再次看到同样内容。

   
第二次Spring AI的开头是
16:17:04.323 [main] DEBUG org.springframework.web.client.DefaultRestClient -- Writing [ChatCompletionRequest[messages=[ChatCompletionMessage[rawContent=# Task
You will be given a **Requirement**, a **Class Diagram** in PlantUML, and a list of operation specifications. Your task is to correct the specifications that are inconsistent with the requirement.

总结:iecoregen 先打印 prompt 原文；
然后 queryString 把 prompt 交给 Spring AI；
Spring AI 发 HTTP 请求时，又把包含 prompt 的 ChatCompletionRequest 打印了一遍。
